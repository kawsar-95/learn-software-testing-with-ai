# Claude Models

Pick the model and the effort level that fit each testing task. A quick test-data fix and a deep root-cause analysis do not need the same model, and the model IDs in your agents and pipelines must stay current.

<PageMeta />

## The current lineup

The current lineup has four models. <Cite n={1} />

| Model | API ID | What the docs say it is for | Latency | Price per MTok (input / output) |
|---|---|---|---|---|
| Claude Fable 5.1 | `claude-fable-5-1` | "For demanding reasoning and long-horizon agentic work" | Slower | $10 / $50 <Cite n={1} /> |
| Claude Opus 5.5 | `claude-opus-5-5` | "For long-running agentic coding and knowledge work" | Moderate | $4 / $20 <Cite n={1} /> |
| Claude Sonnet 5.5 | `claude-sonnet-5-5` | "The best combination of speed and intelligence" | Fast | $2 / $10 <Cite n={1} /> |
| Claude Haiku 5.5 | `claude-haiku-5-5` | "For high-volume, latency-sensitive tasks such as classification, extraction, and routing" | Fastest | from $0.10 / from $0.50 <Cite n={1} /> |

All four models have a 1M-token context window, a 128K-token maximum output, and a reliable knowledge cutoff of Jun 2026. <Cite n={1} /> Actual latency depends on prompt length, output length, and thinking effort. <Cite n={1} />

Every Claude model ID is a pinned snapshot, including the dateless IDs used from the 4.6 generation on. <Cite n={1} />

### Price details

These are Claude API prices. <Cite n={2} />

- Claude Haiku 5.5 costs $0.10 / $0.50 per MTok for prompts up to 100,000 tokens, and $0.50 / $2.50 per MTok for prompts over 100,000 tokens. <Cite n={2} />
- Batch API requests are 50% off. <Cite n={1} />
- Prompt cache reads cost 10% of the base input price: 2.5% on Fable 5.1, and 5% on Opus 5.5 and Sonnet 5.5. <Cite n={1} />

### Tokens and words

On the current tokenizer (introduced with Claude Opus 4.7), 1M tokens is roughly 555k words. Models before it fit about 750k words in 1M tokens. <Cite n={1} /> The newer tokenizer produces approximately 30% more tokens for the same text. <Cite n={2} />

<Callout type="warning" title="Common mistake: the old 0.75 words-per-token rule">

On current models, one token is about 0.55 words, not 0.75. If you estimate cost from word counts with the old rule, your estimate is too low. <Cite n={1} />

</Callout>

To see what a session uses, run `/context` to visualize current context usage, and `/usage` to show session cost, plan usage limits, and activity stats. <Cite n={3} />

## Retired and deprecated models

The model IDs from older versions of this tutorial are retired on the Claude API:

| Model ID | Retired on | Replacement named in the docs |
|---|---|---|
| `claude-opus-4-20250514` | June 15, 2026 | `claude-opus-4-8` <Cite n={4} /> |
| `claude-sonnet-4-20250514` | June 15, 2026 | `claude-sonnet-5-5` <Cite n={4} /> |
| `claude-3-haiku-20240307` | April 20, 2026 | `claude-haiku-4-5-20251001` <Cite n={4} /> |
| `claude-opus-4-1-20250805` | August 5, 2026 | — <Cite n={4} /> |

Claude 3.5 Haiku and Claude 3.7 Sonnet retired on February 19, 2026. <Cite n={4} />

Claude Sonnet 4.5 (`claude-sonnet-4-5-20250929`) is deprecated. It retires on November 30, 2026, and its replacement is `claude-sonnet-5-5`. <Cite n={4} />

A model moves through four states: Active, Legacy, Deprecated, and Retired. Anthropic gives at least 60 days' notice before it retires a publicly released model. <Cite n={4} /> Legacy models that are still available include Claude Fable 5, Claude Opus 5, Claude Opus 4.8, and Claude Haiku 4.5. <Cite n={1} />

For the four current models, Anthropic commits to no retirement before these dates: <Cite n={1} />

- Fable 5.1: September 1, 2027
- Opus 5.5: September 22, 2027
- Sonnet 5.5: September 28, 2027
- Haiku 5.5: October 7, 2027

<Callout type="tip" title="QA tip: search for old IDs">

Search your agent files, scripts, and CI configs for `claude-opus-4`, `claude-sonnet-4`, and `claude-3-`. Replace each retired ID with a current one or with an alias.

</Callout>

## Model aliases in Claude Code

In Claude Code, you can select a model with an alias instead of a full ID. <Cite n={5} />

| Alias | What it selects |
|---|---|
| `fable` | The Fable model for your provider, for your hardest and longest-running tasks <Cite n={5} /> |
| `opus` | The latest Opus model for complex reasoning tasks <Cite n={5} /> |
| `sonnet` | The latest Sonnet model for daily coding tasks <Cite n={5} /> |
| `haiku` | The fast and efficient Haiku model for simple tasks <Cite n={5} /> |
| `best` | The model `fable` resolves to where Fable is available to you, otherwise the same model as `opus` <Cite n={5} /> |
| `opusplan` | `opus` in plan mode, then `sonnet` for code generation and implementation <Cite n={5} /> |
| `default` | Not a model alias. It clears any model override and goes back to the runtime default for your account. <Cite n={5} /> |
| `sonnet[1m]`, `opus[1m]` | The `[1m]` variants of the aliases <Cite n={5} /> |

What the aliases resolve to depends on the provider: <Cite n={5} />

| Provider | `opus` | `sonnet` | `haiku` |
|---|---|---|---|
| Anthropic API | Opus 5.5 | Sonnet 5.5 | Haiku 5.5 <Cite n={5} /> |
| Amazon Bedrock, Google Cloud's Agent Platform | Opus 5.5 | Sonnet 4.5 | Haiku 4.5 <Cite n={5} /> |
| Microsoft Foundry | Opus 4.6 | Sonnet 4.5 | Haiku 4.5 <Cite n={5} /> |

Unless you set `ANTHROPIC_DEFAULT_FABLE_MODEL`, `fable` resolves to Fable 5.1. In Claude apps gateway sessions, `fable` and `best` resolve to Fable 5. <Cite n={5} />

Aliases point to the recommended version for your provider and update over time. <Cite n={5} />

Fable 5.1, Fable 5, Sonnet 5 and later, Haiku 5.5, and Opus 4.7 and later run with the 1M window by default, with no `[1m]` suffix needed. Set `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` to remove the `[1m]` variants. <Cite n={5} />

<Callout type="note" title="inherit is not a session alias">

`inherit` is a value for the `model` field of a subagent. It means "use the same model as the main conversation". <Cite n={6} /> Do not use it as a session model with `/model` or `--model`. See [Models in subagents](#models-in-subagents).

</Callout>

## Which model you get by default

| Account or provider | Default model |
|---|---|
| Pro, Max, Team, Enterprise, and Anthropic API | Opus 5.5 <Cite n={5} /> |
| Amazon Bedrock, Google Cloud's Agent Platform, Claude Platform on AWS | Opus 5.5 <Cite n={5} /> |
| Microsoft Foundry | Sonnet 4.5 <Cite n={5} /> |

Neither Fable model is the default on any plan or provider. To use Fable, select it with `/model fable` or `claude --model fable`. <Cite n={5} /> Fable 5.1 needs Claude Code v2.1.257 or later. Run `claude update` to upgrade. <Cite n={5} />

Depending on the plan and seat tier, Fable usage can bill to usage credits. In that case, the `/model` picker shows "Requires usage credits" on the Fable row. <Cite n={5} />

## Choose a model

### In a session

Run `/model` with an alias or a full name to switch. Run `/model` alone to open a picker. <Cite n={5} />

```text
/model sonnet
```

In the picker, `Enter` switches the model and saves it as your default for new sessions. `s` switches the model for this session only. <Cite n={5} />

### At startup

The `--model` flag and the `ANTHROPIC_MODEL` environment variable apply only to the session you start with them. <Cite n={5} />

```bash
claude --model opus
claude --model claude-sonnet-5-5
```

### In settings

Set the `model` field in a settings file: <Cite n={5} />

```json
{
  "model": "opus"
}
```

When more than one place sets a model, Claude Code uses this order (first wins): <Cite n={5} />

1. `/model` in the session
2. `--model` at startup
3. `ANTHROPIC_MODEL`
4. The `model` field in settings
5. `ANTHROPIC_DEFAULT_MODEL` (needs Claude Code v2.1.236 or later)

To see the current model, look at the status line or run `/status`, which also shows your account information. <Cite n={5} />

### Pin a model and add a fallback

To pin a version, use a full model name such as `claude-opus-5-5`, or set the matching `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL`, `ANTHROPIC_DEFAULT_HAIKU_MODEL`, or `ANTHROPIC_DEFAULT_FABLE_MODEL` variable. `CLAUDE_CODE_SUBAGENT_MODEL` sets the default model for subagents. <Cite n={5} />

`--fallback-model` switches to another model when the primary model is overloaded or not available. It accepts a comma-separated list. <Cite n={7} />

```bash
claude --fallback-model sonnet,haiku
```

<Callout type="tip" title="Suggestion: pin a full model ID in CI">

This is the tutorial's suggestion, not a rule from the docs. Aliases update over time <Cite n={5} />, so a CI job that uses `opus` can change model without a change in your repo. In CI, pin a full model ID such as `claude-opus-5-5`. Then a change in test-analysis output comes from your code, not from a new model.

</Callout>

## Effort levels

Each session also has an effort level. The levels you can use depend on the model.

| Models | Effort levels |
|---|---|
| Fable 5.1, Opus 5.5, Sonnet 5.5, Haiku 5.5 | `low`, `medium`, `high`, `xhigh`, `max` <Cite n={5} /> |
| Opus 4.6, Sonnet 4.6 | `low`, `medium`, `high`, `max` <Cite n={5} /> |

An unsupported level falls back: for example, `xhigh` runs as `high` on Opus 4.6. <Cite n={5} />

In Claude Code, the default effort is `high` on models that support effort, except Opus 5.5, Sonnet 5.5, and Haiku 5.5, which default to `medium`. <Cite n={5} />

### Set the effort

- `/effort` opens a slider. You can also type `/effort <level>` or `/effort auto`. <Cite n={5} />
- In the `/model` picker, the left and right arrows change the effort. <Cite n={5} />
- `--effort <level>` at startup, the `CLAUDE_CODE_EFFORT_LEVEL` environment variable, or `effortLevel` in settings. <Cite n={5} />
- `max` is session-only. The environment variable and the settings key do not accept it as a level. <Cite n={5} /><Cite n={3} />

```bash
claude --effort high
```

To get deeper reasoning for one prompt without a change to the session setting, use the word `ultrathink` in the prompt. <Cite n={5} />

### Which effort to use

| Level | Guidance from the docs |
|---|---|
| `low` | Quick exchanges that you review <Cite n={5} /> |
| `medium` | The default on Opus 5.5, Sonnet 5.5, and Haiku 5.5 <Cite n={5} /> |
| `high` | "Work where verification matters or edge cases are likely" <Cite n={5} /> |
| `max` | "may show diminishing returns and is prone to overthinking, so test before adopting it broadly" <Cite n={5} /> |

The model guide says that tuning effort is often a better lever than switching models. <Cite n={8} />

<Callout type="tip" title="Suggestion: effort for QA work">

This is the tutorial's suggestion. Raise the effort to `high` for root-cause analysis and flaky-test triage, where edge cases matter. Keep `low` or `medium` for formatting, simple test data, and quick questions.

</Callout>

## Models in subagents

The `model` field of a subagent accepts `sonnet`, `opus`, `haiku`, `fable`, a full model ID such as `claude-opus-5-5`, or `inherit`. <Cite n={6} />

Claude Code resolves the model of a subagent in this order: <Cite n={6} />

1. The `model` passed for that one invocation
2. The `model` field in the subagent definition
3. `CLAUDE_CODE_SUBAGENT_MODEL`
4. The model of the main conversation

When you switch with `/model`, the switch also reaches subagents that inherit the model of the main conversation. <Cite n={5} />

Example: a `qa-agent` that always uses Sonnet, and an `sdet-agent` that follows the main conversation.

```yaml
---
name: qa-agent
description: Senior QA engineer. Finds bugs and designs test cases.
model: sonnet
---
```

```yaml
---
name: sdet-agent
description: SDET. Traces code flow and finds the root cause of failures.
model: inherit
---
```

The [Subagents](/extend/subagents/) page explains the other fields.

## Choose a model for QA tasks

The Anthropic model guide gives these starting points: <Cite n={8} />

- Most workloads start with Claude Opus 5.5.
- Use Fable 5.1 for demanding reasoning and long-horizon agentic work, or when your evals at `xhigh` or `max` effort still fall short.
- Use Haiku 5.5 for real-time applications, high-volume processing, cost-sensitive work, and sub-agent tasks.

The guide describes two ways to start: efficiency-first (begin with Haiku 5.5) or capability-first (begin with Opus 5.5). It also tells you to create benchmark tests for your own use case. <Cite n={8} />

<Callout type="note" title="Suggestion: starting models for QA tasks">

The table below is the tutorial's suggestion, not Anthropic guidance. Use it as a starting point and check it with your own tests.

</Callout>

| QA task | Starting model | Why |
|---|---|---|
| Requirement analysis, test design | `opus` | Needs careful reasoning about edge cases |
| Root-cause analysis of a failure across many files | `opus`, or `fable` if the result is still weak | Long, multi-step investigation |
| Daily test writing and code explanation | `sonnet` | Fast, and meant for daily coding work |
| Bulk triage of test logs, classification of failures | `haiku` | High volume, simple decisions |
| Subagents that repeat one small task | `haiku` | Many parallel calls, lower cost |
