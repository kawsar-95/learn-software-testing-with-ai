## End-to-End Workflow

How all three layers connect when you run a real command:

```text
  You type:  /qa-agent payment.js
                │
                ▼
  ┌─────────────────────────────────┐
  │  INTERFACE LAYER                │
  │  commands/qa-agent.md           │  ← resolves /qa-agent → agent instruction
  └──────────────┬──────────────────┘
                 │
                 ▼
  ┌─────────────────────────────────┐
  │  CORE LAYER                     │
  │  agents/qa-agent.md             │  ← sets role + reads SKILL.md files
  │    ├── analyze-requirement       │
  │    ├── find-bug                  │
  │    └── test-design               │
  └──────────────┬──────────────────┘
                 │
                 ▼
  ┌─────────────────────────────────┐
  │  CONTEXT LAYER  (real data)     │
  │  ├── Read  payment.js           │  ← code context
  │  ├── Jira MCP  → ticket #4201   │  ← requirement context
  │  └── DB MCP    → sample rows    │  ← data context
  └──────────────┬──────────────────┘
                 │
                 ▼
        ✅  Bugs found
        ✅  Test cases generated
        ✅  Evidence-backed output
```

## Context Engineering

## Definition

Designing what information the AI sees, not just how you ask.

### ✅ What it focuses on:

- Supplying relevant data dynamically
- Using RAG (Retrieval-Augmented Generation)
- Feeding: Codebase chunks, Jira tickets, Logs, DB data, Commit history

### 💡 Example:

**Instead of:**

```text
Explain this error
```

**You do:**

```text
Context:
- API endpoint: /user/login
- Stack trace: ...
- Related code: (retrieved from vector DB / Attached File)
- Last commits: ...

Task: Analyze root cause
```

## Prompt Engineering vs Context Engineering

| Aspect | Prompt Engineering | Context Engineering |
|---|---|---|
| Focus | How you ask | What AI knows |
| Power | Limited | Massive |
| Accuracy | Medium | High |
| Scalability | Poor | Excellent |
| Use Case | Simple Q&A | Real systems |
| Dependency | Prompt wording | Data quality |
